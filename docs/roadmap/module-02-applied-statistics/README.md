# Module 2 · Applied Statistics & Business Cases

Use the project’s existing Olist and synthetic checkout evidence to make decisions under uncertainty. This module follows Module 1 but uses no Excel or Power Query workflow. Work locally with a calculator, SQL scratchpad, or Python. Use the bundled repository environment for the existing sample-size utility. The tasks below add interpretation or stress tests that the project evidence does not already answer.

## Inputs and conventions

- Olist local files are under `data/raw/olist` from the repository root. Use `olist_orders_dataset.csv` and `olist_customers_dataset.csv`. If the raw files are missing on another machine, use the input setup in the [repository README](../../../README.md). For cases 1, 2 and 5, join on `customer_id`, keep delivered July 2018 purchases in SP or RJ with both delivery timestamps, and use one row per order. Calculate elapsed days by subtracting calendar dates. A delivery is late when the actual delivery **date** exceeds the estimated date.
- Cases 3 and 4 use the existing synthetic arm counts and design in the checkout case study. The 350-row logging loss is a hypothetical incident layered on that evidence.
- Case 6 uses the full local Olist order history and the documented historical GA4 funnel figures. Case 7 uses the checked-in 12-target forecast predictions. Data checks use the delivered-order and session definitions specified by each case.
- The separate [worked solutions](instructor/SOLUTIONS.md) contain numeric checkpoints and decision examples. Finish an attempt before opening them.

## New practical cases

| Case | Do this | Interview question |
|---|---|---|
| **1. Delivery tail** | For SP and RJ, report sample size, mean, median, P90, maximum and count above Q3 + 1.5 × IQR. Use linear interpolation for percentiles. Compare what staffing for a typical day versus a tail day would mean. Inspect outliers before deciding how to report them. | The mean improved but P90 worsened. What would you tell operations and which records would you inspect? |
| **2. Delivery sampling audit** | Take the first 100 eligible SP orders sorted lexicographically by `order_id`. Compute the late share and a 95% Wilson interval as a model-based illustration. Compare with the full SP frame. Design a probability sample across SP and RJ and explain how you would weight a disproportionate allocation. | Would your interval apply to all orders, including undelivered ones? What changes if incomplete orders are systematically delayed? |
| **3. New conversion planning constraint** | Use the existing local sample-size utility to replan the 12% baseline, 80% power, equal allocation case. Evaluate a 1 pp MDE at alpha .05 and the original 2 pp MDE at alpha .01. Hold the original observed result fixed and explain what its p-value can support. | Traffic is capped at the original sample size. What would you change in the experiment proposal, and when must that decision be made? |
| **4. SRM incident drill** | Start with 4,433 users per arm. The analysis export loses 350 B user rows while the assignment ledger still shows equal allocation. Calculate SRM for the export using 1:1 expectation and threshold .001. Write a three-step investigation and a release decision. | The dashboard still shows a significant lift. What would persuade you to trust the result again? |
| **5. Promise length versus delivery time** | Regress actual elapsed days on promised elapsed days and report Pearson r and slope for pooled, SP and RJ samples. Compare slopes, sketch a confounder and propose a design to estimate what changing the promise actually does. | A manager wants to shorten displayed promises because the coefficient is positive. How do you respond? |
| **6. Retention and conversion denominators** | Use delivered purchases to find first observed purchase month per `customer_unique_id`. Compute exact M1 for June and July 2018, and their weighted result under the August cutoff. Explain August’s M1. Then compute an all-session and a view-entry purchase rate from the saved GA4 funnel. Using only desktop and mobile observed rates, compare hypothetical 70:30 and 30:70 desktop/mobile mixes with rates held constant. | Can the overall rate rise while every segment rate stays fixed? How would you prevent a cohort-window change from being reported as growth? |
| **7. Revenue forecast decision** | Read [the 12 saved predictions](../../forecasting/original-predictions.csv). For Naive, MA4 and MA8, score mean loss using one unit for each BRL overforecast and three for each BRL underforecast. Calculate on the same 12 targets. Describe what data must be available at each forecast origin to make a prospective decision. | When would the lowest MAE model be a poor choice even if it won a retrospective comparison? |
| **8. Executive trade-off** | Write a one-page memo to the marketplace lead. Choose one immediate action across delivery, retention, conversion and revenue planning. Give one number with its denominator or window for each area, separate hypotheses from evidence, and propose a gate and owner for the work you defer. | What would change your priority, and which claim would you remove from a board slide today? |

## Study order and demonstration estimate

Work through **1 → 2 → 3 → 4 → 5 → 6 → 7 → 8**. Allow roughly 4–6 hours across two or three sessions. Use the interview question after each computation and the memo as the final review.

- **Strong portfolio evidence** for fixed-horizon conversion inference and power, SRM and guardrail interpretation, observation-aware cohort retention, sequential session conversion, and chronological forecast comparison with uncertainty and leakage caveats. Prepare to walk through an existing artifact and defend a decision.
- **Partial evidence** for exploratory distributions, outlier decisions, sampling design and cross-functional business communication. The repository provides examples and some caveats, while cases 1, 2 and 8 test independent reasoning.
- **Practice needed** for stratified regression and designing a credible causal follow-up. Case 5 adds the missing demonstration. This assessment describes the repository evidence. Personal proficiency requires a walkthrough or an independent attempt.
